# 배포

두 곳에 올라갑니다. 같은 `src/index.html` 에서 나오지만 쓰는 사람이 다릅니다.

| | GitHub Pages (공개) | Claude Artifact (작업용) |
|---|---|---|
| 주소 | https://gnmi93-source.github.io/receipt-split/ | 기존 Artifact URL (고정) |
| 올라가는 것 | `dist/index.html` — 껍데기 씌운 온전한 문서 | `src/index.html` — 조각, 플랫폼이 껍데기 제공 |
| 공유 저장소 | Firebase (계정 없이 누구나) | Artifact `db` |
| 쓸 수 있는 사람 | 링크 받은 **누구나** | 소유자·초대된 편집자·같은 조직 |
| 갱신 | main 머지 시 자동 (1~2분) | 소유자가 손으로 |

**Pages 가 Artifact 보다 앞서 있는 것이 정상 상태입니다.**

---

## 왜 두 개인가

Artifact 의 `db` 는 계정 없는 사람에게 쓰기를 줄 수 없습니다. 권한 모델이 이렇습니다:

| 보는 사람 | 할 수 있는 것 |
|---|---|
| 로그인하지 않은 방문자 | **아무 데이터도 못 봄** — 읽기조차 안 됨 |
| 링크로 들어온 로그인 사용자 | 읽기만 |
| 소유자 · 초대된 편집자 · 같은 조직 | 읽기 + 쓰기 |

어느 설정으로도 "아무나 쓰기" 가 안 됩니다. 구조적 한계이고 우회로가 없습니다
(`room` 은 손님에게 닿지만 아무것도 저장하지 않고 메시지를 흘릴 수 있으며,
`artifact.publish` 는 읽기 전용 방문자에게 거부됩니다).

그래서 공개 배포본은 **정적 호스팅 + 계정 없는 백엔드**로 갑니다. Artifact 배포본은
개발자가 쓰는 작업용으로 남습니다.

## 1. Firebase 설정 (한 번, 소유자가)

후보 6개를 최종사용자·운영·구현 세 관점으로 비교해 고른 결과입니다. 고른 이유는
동시성 모델이 아니라 **전송 계층**입니다 — `experimentalForceLongPolling` 을 켜면
Firestore 가 WebSocket 을 쓰지 않고 평범한 HTTPS 요청의 연속이 됩니다. 카카오톡 인앱
브라우저가 이 앱의 주 경로인데, WebSocket 하나에 목숨을 거는 백엔드는 소켓이 막히는
사람 한 명이 생기면 그 자리에서 할 수 있는 게 없습니다.

그리고 **익명 인증은 계정이 아닙니다.** 로그인 화면도 팝업도 리다이렉트도 없이 uid 가
발급되고, 그 uid 덕분에 보안 규칙이 `request.auth != null` 을 요구할 수 있습니다 —
"계정 없음" 과 "아무나 DB 를 긁어가지 못함" 을 동시에 얻는 유일한 후보였습니다.

### 순서

1. https://console.firebase.google.com → **프로젝트 추가**. Google Analytics 는 끕니다.
2. **Firestore Database** → 데이터베이스 만들기 → **프로덕션 모드** →
   위치는 **`asia-northeast3` (서울)**. 위치는 나중에 바꿀 수 없습니다.
3. **Authentication** → 시작하기 → **익명** 공급자만 사용 설정.
4. **Authentication → Settings → 승인된 도메인**에 추가:
   - `gnmi93-source.github.io`
   - `localhost` (이미 있음)

   > 이걸 빼면 `auth/unauthorized-domain` 으로 실패합니다.
5. **Firestore → 규칙**을 아래로 바꾸고 게시합니다.
6. **프로젝트 설정 → 내 앱 → 웹 앱 추가** (`</>`). 호스팅은 체크하지 않습니다.
   나온 `firebaseConfig` 의 네 값을 `src/index.html` 의 `FIREBASE` 상수에 채웁니다.
7. 커밋 → PR → 머지. Pages 가 갱신되면 공개 주소에서 바로 동작합니다.

### 보안 규칙

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // 방 하나가 정산 하나다. 방 코드는 31글자 알파벳 6자리 — 추측으로 찾기 어렵다.
    // 이 앱의 신원(myId)은 localStorage 기기 ID 이고 권한 축이 아니다.
    // 일부러 그렇게 두었다 — 기기를 바꿨거나 이름을 잘못 집었을 때
    // 빠져나갈 길을 막으면 "아무나 참여" 가 깨진다.
    // 그래서 소유자 기반 규칙(ownerId == request.auth.uid)을 쓰지 않는다.
    // 그 규칙은 이 앱에서 영원히 만족되지 않는다.
    match /rooms/{roomId}/{coll}/{docId} {
      allow read, write: if request.auth != null
                         && roomId.size() == 6
                         && coll in ["meta", "items", "people", "picks", "adjs"];
    }
  }
}
```

막는 것: 로그인하지 않은 접근, 방 목록 전체 훑기, 엉뚱한 컬렉션 생성.
막지 못하는 것: 방 코드를 아는 사람이 그 방을 고치는 것 — 그건 **기능**입니다.

### 무료 한도 (2026-11 확인)

Spark 플랜은 살아 있고 공식 요금 페이지에 "No payment method needed" 로 명시되어
있습니다. Firestore 는 Blaze 전용으로 바뀌지 않았습니다 — 읽기 50,000/일, 쓰기
20,000/일, 저장 1GiB. 모임 한 번이 쓰기 100회 미만이라 일 한도의 1% 수준입니다.

2026년에 Spark 에서 빠진 것은 Cloud Storage(2/3)와 Remote Config(12/1)인데
이 설계는 둘 다 쓰지 않습니다. 다만 **진행 중인 침식**이므로 1년에 한 번은 확인합니다.

**한도를 넘기면 요금이 아니라 그날치 서비스가 멈춥니다.** 방 코드를 아는 누구나
읽기를 태울 수 있으니, 실제 사용자가 늘면 App Check 를 검토합니다 (단, App Check 의
reCAPTCHA 가 카톡 인앱 웹뷰에서 어떻게 동작하는지는 실측이 필요합니다).

### `FIREBASE` 값은 비밀이 아니다

공개 배포본에 그대로 실려야 정상이고, 저장소도 public 입니다 (free 플랜은 private
저장소에서 Pages 와 브랜치 보호를 못 씁니다). **접근 제어는 키가 아니라 위의 보안
규칙이 합니다.** 반대로, 진짜 비밀은 이 저장소에 **절대** 커밋하지 마십시오 —
public 저장소의 push 이력에 영원히 남습니다.

### 설정이 비어 있으면

`FIREBASE.apiKey` 가 비어 있으면 공개 배포본은 **이 브라우저에만 저장** 모드로
떨어집니다. 화면은 전부 동작하고 계산도 맞지만 공유가 안 되고, 배너로 그렇게 알립니다.
SDK 를 못 받았거나 익명 로그인이 꺼져 있을 때도 같은 모드로 떨어집니다.

## 2. 방 코드

주소의 `#r=ABC-DEF` 가 정산 하나를 가리킵니다. 해시가 없으면 새 방을 만들어
주소에 적어 둡니다 (`replaceState` — 뒤로 가기가 방을 되돌리면 안 됩니다).

헷갈리는 글자(`0 O 1 I L`)를 뺀 31글자 알파벳에서 6자리를 뽑습니다 (약 9억 가지).
전화로 불러 줄 수 있어야 하기 때문입니다 — 복사가 막힌 인앱 브라우저에서
"방 코드 ABC-DEF 를 알려 주세요" 로 빠져나갑니다.

쿼리스트링이 아니라 **해시**인 이유: 일부 인앱 브라우저의 링크 미리보기와 리다이렉트가
쿼리를 잘라냅니다. 해시는 서버로 가지 않으니 Pages 의 하위 경로 서빙에도 안전합니다.

## 3. Artifact 재배포 (소유자만, 손으로)

자동화할 수 없습니다. Artifact 재배포는 Claude Code 세션을 통해서만 일어나고
Artifact 는 한 계정의 소유물입니다 — GitHub Actions 에서 호출할 API가 없습니다.
그래서 목표를 "자동화" 가 아니라 **"수동 단계가 잊히지 않게"** 로 둡니다:
main 이 갱신되면 CI 가 고정된 `Artifact 배포 대기열` Issue 에 커밋을 기록합니다.
그게 Artifact 가 얼마나 뒤처져 있는지의 유일한 기록입니다.

### 주기

- `artifact-deploy` 라벨이 붙은 PR 이 머지되면 **그날 안에** (계산 버그, 눈에 보이는 고장)
- 그 밖에는 **주 1회**. 문서·CI·테스트만 바뀐 머지는 재배포하지 않습니다.

### 체크리스트

```powershell
git switch main; git pull

node tools/build.mjs --check
node tests/split.test.mjs
node tools/build.mjs
Start-Process dist\index.html          # 눈으로 먼저

# 지난 재배포 이후 들어간 것
git log --oneline (git describe --tags --abbrev=0 --match "artifact-*")..HEAD
```

그리고 Claude Code 에서 **`src/index.html` 을** 기존 Artifact URL 로 재배포합니다.
반드시 지킬 것:

- **기존 URL 로 올립니다.** 새 Artifact 를 만들면 카톡으로 이미 공유된 링크가 전부 죽습니다.
  올리기 전에 현재 버전을 읽어야 합니다 (읽지 않은 Artifact 로의 배포는 거부됩니다).
- **`dist/index.html` 을 올리지 않습니다.** 껍데기가 이중으로 씌워집니다.
- **favicon 은 생략합니다.** 재배포 때 빼면 기존 아이콘이 유지됩니다.
  바꾸면 사용자 탭에서 다른 페이지로 보입니다.
- capabilities 는 `{ db: {}, sample: { images: true } }`. `user` 는 쓰지 않습니다 —
  아바타·프로필은 로그인한 Claude 사용자에게만 동작해서 두 계급 UI 를 만들었습니다.

```powershell
git tag "artifact-$(Get-Date -Format yyyyMMdd)"
git push origin --tags
gh issue comment <대기열번호> --body "Artifact 재배포 완료 — $(git rev-parse --short HEAD) 까지 반영"
```

### 되돌리기

코드의 진실원본은 git 입니다. Artifact 쪽만 이전 버전으로 되돌리면 git 과 어긋난 채로
남아 다음 재배포가 되돌림을 덮어씁니다. **먼저 `git revert <sha>` 로 main 을 되돌리고
그 상태를 재배포합니다.**

### Artifact → git 방향은 없다

Artifact 를 직접 편집하면 git 으로 돌아오는 경로가 없어서 다음 재배포가 그 편집을
덮어씁니다. 소유자도 예외가 아닙니다. 급히 고치고 싶어지면 같은 변경을 PR 로 올려
머지한 뒤 재배포합니다.

Artifact 가 세션 밖에서 바뀌어 git 과 어긋났다면, Claude Code 에서 Artifact 를 먼저 읽어
`src/index.html` 과 비교하고 필요한 변경을 PR 로 되돌려 넣은 다음 재배포합니다.
