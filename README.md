# 영수증 정산기

영수증 사진에서 메뉴와 가격을 자동으로 읽고, 여러 사람이 **동시에** 각자 먹은 메뉴를 고르면
공동 메뉴와 할인까지 반영해 1인당 정산 금액을 계산한다.

**공개 주소** → https://gnmi93-source.github.io/receipt-split/

앱의 **초대** 버튼을 누르면 링크가 복사된다. 그걸 카톡에 붙이면 받은 사람은
**아무 계정 없이** 바로 들어와 자기가 먹은 메뉴를 고른다. 링크의 `#r=ABC-DEF` 가
정산 하나를 가리키므로, 복사가 막힌 인앱 브라우저에서는 그 여섯 글자만 불러 줘도 된다.

개발자용 작업 배포본은 Artifact 에 따로 있다 — [docs/배포.md](docs/배포.md) 참고.
거기서는 Claude 계정과 편집 권한 초대가 필요하다. 그 제약이 공개 배포본을 따로 두는 이유다.

## 동작

| 기능 | 설명 |
|---|---|
| 영수증 사진 인식 | 폰에서는 **영수증 찍기**로 카메라를 바로 열고, 찍은 사진은 긴 변 1600px 로 줄여 보낸다. 메뉴·단가·수량·할인·결제금액을 읽어 목록으로 만들고, 추가하기 전에 사람이 확인한다. **지금은 Artifact 배포본에서만 된다** — 공개 배포본에는 인식기가 없어서 버튼 자체가 보이지 않는다. |
| 계정 없는 실시간 공유 | 한 링크를 여러 명이 동시에 열고 각자 자기 메뉴를 고른다. 모든 변경이 바로 서로에게 보인다. 로그인·설치 없음. |
| 내 이름 가져가기 | 참여자 칸에서 **내 이름**을 누르면, 그 사람의 메뉴만 큰 버튼으로 골라 담는 화면이 열린다. |
| 공동 메뉴 분할 | 한 메뉴를 여러 명이 고르면 금액을 고른 사람 수로 나눈다. |
| 할인·추가금 안분 | 쿠폰·통신사 할인·봉사료를 각자 담은 금액 비율대로 반영한다. |
| 1원 단위 보정 | 나머지 1원까지 나눠, 사람별 금액의 합이 결제 총액과 **정확히** 같다. |
| 총액 대조 | 영수증에 인쇄된 금액을 적어 두면 어긋날 때 알려 준다. (사진 인식 오류 잡기) |
| 결과 복사 | 카카오톡에 붙일 수 있는 텍스트로 복사한다. |

계산 규칙의 정확한 정의는 [docs/정산-규칙.md](docs/정산-규칙.md) 에 있다. **금액 로직을 건드리기 전에 반드시 읽는다.**

## 구조

```
영수증-정산기/
├── src/index.html          앱 전체 (단일 파일: 마크업 + CSS + JS)
├── tools/build.mjs         src 조각 → dist/index.html (정적 호스팅용) + CI 검사
├── tests/split.test.mjs    정산 계산 검증 — src 에서 함수를 직접 추출해 테스트한다
├── docs/정산-규칙.md        금액 분할·할인 안분·1원 보정 규칙의 기준 문서
├── docs/배포.md             Firebase 설정, 보안 규칙, Artifact 재배포 절차
├── CONTRIBUTING.md         여러 명이 단일 파일을 고칠 때의 충돌 규칙
└── .github/workflows/      ci.yml (PR 검사) + pages.yml (main → 공개 주소)
```

`src/index.html` 은 `<!DOCTYPE>` / `<html>` / `<head>` / `<body>` 태그가 없다.
Artifact 로 배포될 때 플랫폼이 그 껍데기를 씌운다. 그래서 `<title>`, `<link>`, `<style>` 이 파일 맨 위에 바로 온다.
정적 호스팅에 올릴 때는 `tools/build.mjs` 가 **플랫폼과 똑같은 껍데기**를 씌워 `dist/index.html` 을 만든다.
두 배포본이 다르게 보이면 한쪽에서만 재현되는 버그가 생기므로, 껍데기(`RESET`)를 고칠 때는 플랫폼 쪽과 맞춘다.

## 개발

```powershell
# 계산 로직 테스트 (의존성 없음, Node 18+)
node tests/split.test.mjs

# 조각 검사 — 껍데기 태그·<title>·JS 문법·테마 분기 (CI 가 같은 걸 돌린다)
node tools/build.mjs --check

# 정적 배포본 만들기
node tools/build.mjs
```

`--check` 가 막는 것:

- 조각에 `<!doctype>`/`<html>`/`<head>`/`<body>` 가 들어간 경우 — Artifact 배포가 깨진다
- `<script>` 안의 문법 오류 — 앱이 한 파일이라 오류 하나가 **화면 전체**를 날린다
- 테마 색 분기가 `:root` 토큰 블록 밖에 있는 경우 — 미디어 쿼리 밖의
  `:root:not([data-theme="light"])` 는 **라이트 기본 상태에서도 매치된다.**
  실제로 이 버그가 다섯 군데 있었다. 색은 `:root` 세 블록의 토큰으로 정의하고 규칙에서는 `var()` 로만 쓴다.

### 배포

| | GitHub Pages (공개) | Claude Artifact (작업용) |
|---|---|---|
| 올라가는 것 | `dist/index.html` | `src/index.html` |
| 갱신 | main 머지 시 자동 | 소유자가 손으로 |
| 쓸 수 있는 사람 | 링크 받은 **누구나** | 소유자·초대된 편집자 |

**Pages 가 Artifact 보다 앞서 있는 것이 정상 상태다.** 절차와 Firebase 설정은
[docs/배포.md](docs/배포.md) 에 있다. Artifact 를 직접 편집하지 말 것 — git 으로 돌아오는
경로가 없어서 다음 재배포가 그 편집을 덮어쓴다.

### 공유 데이터 구조

세 가지 저장소를 같은 네 메서드 인터페이스(`write`/`remove`/`writeMeta`/`subscribe`)로 쓴다.
부트스트랩이 되는 것을 순서대로 고른다.

| 어댑터 | 언제 | 쓰기 가능한 사람 |
|---|---|---|
| `artifactAdapter` | Artifact 안 (`window.claude.db`) | 소유자·편집자 |
| `firebaseAdapter` | 공개 배포본, `FIREBASE` 설정이 채워져 있을 때 | **누구나** (익명 인증) |
| `localAdapter` | 그 밖 — 파일을 직접 열었거나 설정이 비었을 때 | 나만 (공유 안 됨) |

어느 쪽이든 문서 모양은 같다. 방 하나가 정산 하나이고, 모든 참여자가 같은 문서를 본다.

| 경로 | 내용 |
|---|---|
| `meta/session` | `{ title, receiptTotal }` |
| `items/{id}` | `{ name, unitPrice, qty, order }` |
| `people/{id}` | `{ name, order, claimedBy }` |
| `picks/{personId}~{itemId}` | `{ personId, itemId }` |
| `adjs/{id}` | `{ label, kind: discount\|extra, mode: amount\|percent, value, order }` |

**메뉴 선택 하나가 문서 하나다.** 이 구조를 깨지 말 것 — 이유가 있다.

어댑터에는 부분 수정 수단이 없다. 문서를 쓰면 **문서 전체가 덮어써진다.**
그래서 선택을 `people/{id}` 안의 맵(`picks: { itemId: 1 }`)으로 두면, 누가 이름을 고치는 동안
다른 사람이 메뉴를 고르면 **늦게 도착한 쓰기가 먼저 것을 지운다.** 한 사람 문서를
두 기기가 같이 쓰면 더 심하다.

선택을 문서로 쪼개면 선택은 *문서 하나를 만들거나 지우는 일*이 되어 읽고-고쳐-쓰기가 사라진다.
겹칠 데가 없으니 몇 명이 동시에 골라도 안전하다.

계산 코드(`compute`)는 여전히 `p.picks` 모양을 본다 — 읽기 경로의 `applyPicks()` 가
`picks` 컬렉션을 사람별 맵으로 조립해 준다. 그래서 저장 구조를 바꿔도 계산 코드와 테스트는 그대로다.

필드 일부만 고칠 때는 `patch(coll, id, fields)` 를 쓴다. 본문을 **큐가 실행되는 순간**의
`state` 로 만들기 때문에, 기다리는 동안 들어온 남의 수정을 덮어쓰지 않는다.
`put(coll, id, body)` 는 새 문서를 만들 때만 쓴다.

쓰기는 문서별 큐를 거친다(`enqueue`). 텍스트 입력은 420ms 디바운스 후에 저장한다.

### 내가 누구인지

계정 없는 사람도 참여해야 하므로, 신원은 브라우저마다 한 번 만드는 무작위 ID(`myId`, localStorage)로 잡는다.
참여자 칸에서 **내 이름**을 누르면 그 사람 문서의 `claimedBy` 에 내 ID 가 들어간다.

이 ID 는 이름을 집는 데만 쓰고 **권한 판단에는 쓰지 않는다.** 남이 집어 둔 이름도 누를 수 있다 —
기기를 바꿨거나 잘못 집었을 때 빠져나갈 길을 막으면 안 된다.
브라우저를 바꾸거나 시크릿 창으로 들어오면 다른 사람으로 보이고, 그때는 자기 이름을 다시 누르면 된다.

### 방 코드

주소의 `#r=ABC-DEF` 가 정산 하나를 가리킨다. 해시가 없으면 새 방을 만들어 주소에 적어 둔다.
헷갈리는 글자(`0 O 1 I L`)를 뺀 31글자에서 6자리를 뽑으므로 전화로 불러 줄 수 있다.
쿼리스트링이 아니라 해시인 이유는 일부 인앱 브라우저가 링크 미리보기에서 쿼리를 잘라내기 때문이다.

## 함께 고치기

여러 명이 각자의 아이디어로 이 앱을 고친다. 앱이 단일 HTML 파일이라 충돌 규칙이 중요하다 —
**브랜치를 따기 전에 [CONTRIBUTING.md](CONTRIBUTING.md) 를 읽는다.** 요약하면:

- `main` 직접 push 금지. PR + 리뷰 1명 + CI 통과. 머지는 squash.
- `git config core.autocrlf false` — 안 하면 파일 전체가 변경으로 잡혀 남의 PR 을 전멸시킨다.
- 아이디어는 먼저 Issue 로 올리고 `area:*` 라벨을 붙인다. 같은 영역에 먼저 붙은 사람이 있으면 먼저 이야기한다.
- 금액 계산을 바꿨다면 [docs/정산-규칙.md](docs/정산-규칙.md) 를 **먼저** 고치고
  `tests/split.test.mjs` 에 그 경우를 추가한다. CI 의 `rules-doc` 검사가 이 순서를 확인한다.

테스트는 `src/index.html` 에서 함수를 문자열로 추출해 실행하므로, 함수 이름(`compute`, `largestRemainder`, `sorted`, `num`)을
바꾸면 테스트가 먼저 깨진다. 의도된 장치다.

## 아직 안 한 것

- 수량 가중치 (한 메뉴를 1.5인분 / 0.5인분으로 나누기)
- 정산 이력 — 한 방에 한 건의 정산만 담긴다. 모임마다 새 링크를 만들어 쓴다.
- 연결이 끝까지 안 되는 사람을 위한 2차 수단 — 상태를 링크 해시에 압축해 넘기기
- 송금 링크 연결
